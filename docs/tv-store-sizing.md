# Per-store TV sizes: X4

Jorge approved restoring the existing per-store text sizing on 21 September.
This corrects the behavior promised by #277, not the board's design. No CSS,
controls, copy, row-sizing formula or animation timings change. The visible
difference is that a rotating store now uses its own selected size.

## What was wrong

The size picker lived in `loop()`, but the automatic convoy calls
`renderStore()` directly. Switching from an 80% store to a 120% store kept 80%,
even through the next refresh. This predates the verbatim extraction in #409.

Saving the visiting store also put its `tscale` in the home screen's general
display record. On reopening, the legacy migration could treat that visitor's
size as the home's old preference when home had no explicit per-store override.

The new tests also exposed an awaited-save race: after fetching the home row,
the save used the store currently in `CFG`, which could have rotated since the
press. During the convoy itself, that identity changed before the visible swap.

## Repair

- Pick the size in `renderStore()` before rendering: screen-specific override,
  then the arriving store's published size, then 100%. Same-store refreshes
  still preserve an in-progress slider adjustment.
- Save text size only under its store-specific local key. Keep the home record
  for the screen's other settings, without `tscale`.
- Preserve the legacy migration for genuine older settings. Never replace an
  explicit home override with a visitor's size.
- Capture store, display and current row at Save. Commit the arriving store's
  identity at the existing covered swap, with the same convoy timing.
- Do not claim a local save worked if the size write failed. If the home row
  cannot be read for a shared save, retain the local save and show the existing
  local-only result instead of publishing an invented 100% home size.

Text size is per store. Squeeze, inset, background, style and the rotation list
remain screen-wide, as before. This is not automatic per-store layout redesign.

## Verification and limits

The tests execute the actual script generated by `LEADERBOARD_HTML`, including
the real convoy callbacks and Save handler, with stand-ins for the network,
drawing and clock. Seven of the initial ten tests failed before the fix. The
final thirteen cover both rotation directions, local/published/default sizes,
refresh, home and visitor saves, reopen, legacy migration, save races, storage
failure and failed home reads.

Local browser fixture: fifteen fictional associates at 80%, three at 120%.
Using the real board controls, the smaller store was changed to 125% and saved.
Reload restored the large store to 80%; rotating again restored the small store
to 125%. No console errors detected. A fixture-only Next store button invokes
the real convoy without waiting for the automatic dwell. The fixture holds the
automatic dwell for inspection; no such controls or timing overrides ship.
An initially malformed threshold fixture was corrected, and the final template
was reloaded and checked again. This was test data, not an application change.

All 623 tests and the production build passed locally. The local
feel harness cannot launch because the work PC lacks its Playwright browser;
CI Chromium and WebKit must pass before merge. No live store records or real TV
settings were changed, and physical dealership TVs were not tested.

Already-contaminated stored preferences cannot be distinguished reliably from
intentional settings. This patch does not delete them or guess replacement
sizes. A screen with an old wrong preference may need its size adjusted and
saved once for each affected store after deployment.

Claude's C84, rotation lost after a template-download fallback to `?board=`, is
separate and unchanged. Review especially the save snapshot and the removal of
