## What is wired

prepareManualServerAdapter allocates a separate identity client per bearer request and calls the existing createManualSchedulerServer. Existing createSchedulerIdentityReader calls auth.getUser(token), then reads only id,role,stores,active,pending from profiles by the verified user ID. No getSession, decoded JWT, body actor or mutable shared auth session is used. The future createRequestClient must construct a fresh publishable-key client scoped to that bearer with session persistence and automatic refresh disabled. The adapter neither creates this client nor reads any credentials. Its injected factory is trusted code: tests do not prove it is nonprivileged or that real profile RLS permits the read.

The runtime transport must be the existing createSchedulerPgTransport with publicationV2:true over scheduler_runtime, with its existing URL/TLS validation unchanged. draftPermissionFor invokes only the existing draft_permission RPC and requires a boolean response. Manager/admin review keeps the existing active, approved, profile-store and explicit publish-grant checks. Draft actions retain their explicit pilot and action-grant rules. Own reads pass only verified actor, store and month to own_published_v2; SQL, not client filtering, resolves floor_people.user_id/store to person_id and locks/rechecks active/approved status. A linked pending person stays schedulable but cannot read. No role permissions are expanded.

The actor-bound capture port exposes only snapshot/register/context to composition. putPolicy maintenance is omitted. Publication still validates the captured digest, actor and scope, and SQL checks the current publication grant at commit. Policy is read from the existing coherent capture contract, never defaulted or supplied from the request.

## Restricted capability contract, local implementation only

capture-executor.sql is a review-only, one-time migration candidate, applied ONLY to disposable fake-data PostgreSQL. It creates scheduler_capture_executor as NOLOGIN, non-superuser, non-BYPASSRLS, no role creation or table ownership. Runtime has no membership in it. Narrow actor-bound gateway functions run as that executor; public/anon/authenticated/service_role receive no execution. The non-login definer receives only listed source reads and capture context/pointer writes, with RLS. It cannot edit app_data, policy/grants, published bindings or immutable contexts. Existing raw capture functions remain inaccessible to runtime.

publication_permission_v1 runs as the existing scheduler_executor. It takes profile, scope and grant FOR SHARE locks in the same order as publish_v2 and checks exactly the existing active/approved manager/admin, profile-store, enabled scope and explicit grant rules. Capture snapshot, register and context each call it afresh. A prior true boolean never authorizes later execution. Commit-time publish_v2 checks are unchanged.

register_capture_v2 additionally binds context schema, scope, epoch, expected head and audit actor to the verified request actor. The existing raw registration performs exact current snapshot CAS under the store lock, followed by atomic immutable context insertion and source-pointer update. It still trusts strict JS assembly/review/projection. SQL structural checks DO NOT independently recompute planner correctness. The actor parameter is a trusted server assertion, not SQL JWT verification. Never expose these gateways directly to browser roles.

restricted-capabilities.mjs wraps an injected runtime pool with fixed parameterized statements. Each operation is its own bounded transaction and checks both current_user and session_user are scheduler_runtime and neither superuser nor BYPASSRLS. Pools created as an owner with SET ROLE are refused. No pool/credential is created or read. Ports bind actor/store/month once. The request adapter first verifies getUser and refuses a later identity switch, then uses capturePortFor with that immutable identity/scope; no raw request actor or policy writer is admitted.

The installer follows existing temporary role-transfer conventions, revoking temporary membership and schema CREATE before commit. Runtime receives only named gateway EXECUTE. No LOGIN or account grant is installed. The disposable test alone gives scheduler_runtime LOGIN to exercise a real restricted session. Installation is not automatic and an existing conflicting role makes CREATE ROLE fail closed.

Remaining hosted prerequisites: review the exact installer against the isolated project's actual schema/RLS/role ownership; verify real token-scoped profile visibility and server pool identity; seed approved explicit policy and boundary drafts through separately approved setup; ensure the capture capability stays server-private and no untrusted code can submit fabricated reviewed contexts. No service-role or database-owner shortcut is permitted. These are hosted verification requirements, not missing code-level capture/permission interfaces.
