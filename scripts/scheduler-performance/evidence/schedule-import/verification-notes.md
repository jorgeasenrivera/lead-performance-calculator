# Schedule import verification

Scope: isolated fictional preview, starting at 80040e28c8e38cb23e2e3983d81ef722990865bf. No production source, production writes, persistence, access settings, writer claims or external upload services changed.

Model tests cover exact minute intervals and coverage gaps; split-person continuous coverage; deduplication; legacy full days; manual/fixture preservation; strict real dates; unsupported DST/overnight/timezones/times; malformed and oversized CSV; source provenance; ambiguous names; explicit skips; duplicate batches/imports and double Apply; stale assignments/settings/reset/changed-then-restored values; composite store identity; work/off conflicts; overlaps; weekly caps across months and years in both directions; closed/unknown store hours and availability; integer-minute cap arithmetic. Overnight, DST-change dates and break columns are rejected, not claimed as supported scheduling policies. Role and overtime policies have no configured input and are not inferred.

Browser import cases cover 1440/390/320px at 100%/200% root text in Chromium and WebKit. Checks include file errors, escaped untrusted names, identity selection, blocked off/work conflicts, explicit skip, cancel, exact applied times, manual preservation, duplicate/double Apply, delayed-read cancellation, newer-read supersession, store-change invalidation, visible keyboard focus, no horizontal page overflow, scoped axe scans, zero import network requests, unchanged local/session storage and zero instrumented Storage/IndexedDB/beacon calls. The full Performance coherent-flow regressions are also run in both engines.

Intermediate findings: the first focus probe checked a programmatically focused button while the browser remained in pointer modality. The final probe enters keyboard modality with Tab and verifies the existing focus-visible outline. Visual review caught skipped off rows losing their status/identity in the review display; those facts are now retained. Duplicate-only completion originally invalidated the current month review flag; it now leaves draft state unchanged. Draft revisions prevent stale-review acceptance after changes are restored to identical values. Final results use the corrected source.

Existing paper/forest tokens, pixel icons, panel styles and focus outlines are reused. Screenshots include escaped synthetic markup as an input-safety case, not a real person's name or private attachment.

Security boundary: a fictional manager can read/review/apply an in-memory store draft; identical person IDs in another fictional store remain isolated. There is no staff-facing published import, server authorization, database transaction, durable audit or publish operation in this scope. Those live controls are untested, not passed. OWASP ASVS 5.0.0 overview was consulted (https://owasp.org/projects/asvs); no ASVS certification or complete requirement-level audit is claimed.

Limits: no physical devices, screen-reader session or actual browser menu zoom. Text scaling uses the root font. WebKit flow swipe events are synthetic. Hosted authenticated rendering depends on environment access; no protection bypass is authorized. Production-sized operational schedules beyond the bounded 500-row input are not benchmarked.
