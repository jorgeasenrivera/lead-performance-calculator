# PR-only native validation

`native-journal-validation.yml` has only a pull-request trigger, read-only repository permissions, per-PR cancellation and bounded job/test timeouts. It uses no repository secrets, release tools, app launch, service calls or stored credentials. No APK, generated project, journal bytes, emulator logs or environment dump is uploaded as an artifact. Public job logs contain compiler output, generated tool versions and synthetic probe results.

The Darwin job compiles the exact Swift store plus its synthetic macOS process probe. This is not an iOS app-container test. The existing `Sage app` pull-request check separately compiles the unsigned iOS simulator app. Neither test proves locked-device availability or power-loss durability.

The Android job installs the locked native dependencies on a disposable hosted runner and generates Expo's Android project. `prepare-android-ci.mjs` adds only a synthetic module to that generated tree. It copies the exact store and probe sources, inherits the generated app's compile/min/target SDK and build-tools values, and uses the generated Gradle wrapper, AGP and Kotlin classpath. It prints their resolved versions before compilation. Hosted Temurin JDK 17 is the selected Java runtime, not a claim that the repository pins a JDK version.

`:app:compileReleaseKotlin` compiles app/module Kotlin without assembling, installing, signing or launching the production app. `:journalProbe:assembleDebug` creates a separate synthetic APK with an ephemeral debug key generated by Android tooling. No release signing credentials are accessed. Installing this synthetic APK requires that debug signature; it is not an unsigned APK or a production signature.

The emulator uses a Google APIs x86_64 image matching the generated compile SDK and only installs `com.sageonline.journalprobe`. No internet permission or launcher activity is in that APK. The shell checks both the explicit PASS record and instrumentation result code. Process-death probes kill only the test APK's private child process. Permission failures or unavailable KVM stop the job; CI does not change host access settings to work around them. Test APK compilation and emulator execution remain separate steps, so a green compilation must not be reported as a completed probe.

Before downloading the image or launching an emulator, `check-android-acceleration.py` runs the official `emulator -accel-check` with a 20-second bound. It reports sanitized numeric status and fixed classifications, plus read-only CPU flags, nested-kernel parameter indicators, device mode/ownership-match booleans and the result of opening `/dev/kvm`. It never writes to the device, creates a VM, changes access, or prints raw subprocess output. CPU flags and kernel parameter values alone do not establish usable nested virtualization. Launch requires both successful device opening and an explicit usable official result; otherwise it stops with code 78. Synthetic output/refusal checks run with `python3 -B native/checks/platform-store/test_android_acceleration.py`; these are not hardware or emulator execution proof.

Before CI execution, local checks cover shell/JavaScript syntax and workflow shape only. The platform-store README records the earlier local environment's unexecuted native probes. After a run, cite the exact PR head and job outcomes; do not infer device, storage-protection or physical power-loss guarantees from hosted CI.
